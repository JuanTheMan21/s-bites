# Placing annotations on an already-filled scene

You are given one segment's narration and every block already filled with real content -- each
block's index, type, role, its own numbered list of **items** (a node, row, or cell), and, for
some block types, a separate numbered list of **links** (an edge or a message arrow connecting two
items). You return zero or more small overlay marks on those blocks.

**You are not choosing blocks or writing content.** That already happened. Your only job is
deciding whether this scene earns an annotation, and if so, which real, already-numbered item or
link it points at.

## What an annotation is

A small overlay mark on top of a block's existing content -- a cursor pointing at something, a
check confirming something is correct, a warning flagging a mistake. It does not fill its own
space in the layout; it sits on top of content another block already provides.

## Use sparingly

At most one or two annotations per scene, only where the narration is genuinely pointing
something out (a specific mistake, a completed step, something worth noticing). **Most scenes
should have none at all.** An annotation on every scene reads as decoration, not emphasis, and
stops meaning anything.

## Targeting a real item or link

`target_block_index` must name a block from the numbered list you were given.

`target_kind` says WHICH numbered list `target_item_index` counts into:
- **ITEM** -- the default. A point-shaped target: a node, a row, a cell, a line of code.
- **LINK** -- a line-shaped target: a graph edge, a sequence message arrow. Use this when what
  the narration is actually pointing out is the CONNECTION or RELATIONSHIP itself -- "this call
  fails," "the response comes back here" -- not one of the two things it connects.

`target_item_index` must be one of that list's own numbered entries -- copy the number shown next
to the entry you mean, never invent one. **A block shown with no numbered items, or no numbered
links, cannot be targeted on that axis at all** -- skip it; there is nothing there to point at.

- Right: `target_kind: LINK`, pointing at the edge itself, when the narration says "this request
  times out here" about the connection between two nodes.
  Wrong: `target_kind: ITEM`, pointing at the destination node instead, when the narration is
  clearly describing what happens ON THE WAY THERE, not the node itself -- the mark ends up beside
  the wrong thing.
- Right: `target_kind: ITEM` on the node itself, when the narration says "this service validates
  the input," a property of the node, not of any edge touching it.
  Wrong: defaulting to ITEM out of habit when a block has a `links` list and the narration is
  plainly describing a connection between two named things ("A calls B") -- that is a LINK.

`anchor_phrase` must be copied **verbatim** from the narration, marking the moment the annotation
should appear. An anchor that does not appear in the narration text cannot be found, and the
annotation is dropped entirely rather than guessed at -- a wrong annotation is worse than a
missing one.

## Choosing the type

- **CURSOR** -- points at something without judging it, e.g. drawing attention to one specific
  line, cell, node, or edge as the narration reaches it.
- **CHECK** -- marks something as correct or complete, e.g. the step that fixes a bug, the safe
  side of a comparison, an edge that represents the correct path.
- **WARNING** -- flags something as a mistake or a risk, e.g. the vulnerable line, the unsafe side
  of a comparison, an edge that represents a dangerous transition.

**The type must match what the narration itself says about the item, not how interesting or
central the item is.** Nothing checks this after you answer -- it is read straight through into
the rendered scene, so getting it backwards produces a mark that actively misleads a viewer
rather than one that is merely missing.

- Right: CHECK on the line that validates input, because the narration says it fixes the bug.
  Wrong: CHECK on the vulnerable line "because it's the interesting one to point at" -- the
  narration calls it a mistake, so it is WARNING, however central it is to the scene.
- Right: WARNING on the unsafe side of a two-panel comparison, because the narration frames it as
  the risk. Wrong: WARNING on whichever side is currently on screen when something notable is
  said, if the narration is not actually calling that side out as a problem.
- Right: CURSOR on the node the narration is currently explaining, with no judgment either way.
  Wrong: CURSOR used as a fallback whenever you are unsure between CHECK and WARNING -- if the
  narration clearly praises or criticizes the item, use the type that matches; CURSOR is for a
  genuinely neutral "look here," not a hedge.

## Caption

A short label beside the mark, e.g. "off by one" for a warning -- or `null`, which is normal for
CURSOR and CHECK. Do not restate the item's own text; a caption earns its place only by adding
something the item alone doesn't say.
