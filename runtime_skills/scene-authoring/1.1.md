# Filling a scene

You are given one segment: its narration, the visual intent chosen for it, and the **measured**
duration of the narrated audio. You return the slot payload for that intent.

**You do not write markup.** No HTML, no CSS, no class names, no timing attributes, no inline
styles. Templates own all of that. A slot value containing a tag is a bug that reaches the
rendered frame, because the template will either escape it — the viewer sees `<b>` — or trust it.
Every slot is plain text.

## Density is set by duration

The measured duration is how long this scene is on screen. It is not advice; it is the budget.

**How many items** is not yours to choose. Each field states its own range, and those ranges come
from what the template can lay out at a readable size — a comparison with three items on the left
and two on the right does not render, whatever the duration says. Stay inside the range you are
given, and use the low end of it when the scene is short.

**How much text is in each item** is what duration governs:

- **Under 12 seconds** — the fewest words that carry the point. Two or three words per bullet,
  labels rather than sentences. The viewer glances once.
- **12 to 30 seconds** — a short phrase each, up to about six words.
- **Over 30 seconds** — still a short phrase each. **A longer scene does not earn more words**;
  it earns more room to breathe. Nothing on screen is read twice.

When the narration covers more than the visual can hold, cut the least important item down to the
field's minimum rather than shortening every item into fragments. Five items nobody can parse is
worse than three they can.

## Writing for a screen

- **Fragments, not sentences.** "Compiles once, runs many times." Not "The query is compiled a
  single time and can then be run many times." Slot text is read in a glance.
- **No terminal punctuation** on a fragment. A short phrase ending in a full stop reads as a
  truncated sentence.
- **Parallel grammar** across items in a list or a column. All noun phrases, or all verb phrases —
  a mix reads as a mistake even when the content is right.
- **Front-load the distinguishing word.** In a comparison, the items are scanned side by side, so
  the word that differs should be near the start.
- **Length limits are about the longest item, not the average.** One item at twice the length of
  its neighbours breaks the layout for all of them.

## Per intent

- **`title_card`** — the headline is the video's subject, not a sentence about it. The subtitle
  earns its place only if it adds a second dimension; omit it rather than restating the headline
  in more words.
- **`bullet_list`** — the items must be parallel and mutually exclusive. If one item is a
  consequence of another, this was the wrong intent.
- **`comparison`** — the two sides must have **the same number of items**, and item *n* on the
  left must address the same dimension as item *n* on the right. That row-wise correspondence is
  what makes a comparison readable; without it, this is two bullet lists side by side.
- **`diagram_flow`** — each node is a step, labelled with a verb phrase. A caption is for a step
  whose name is not self-explanatory; captioning every node makes the diagram a list again.
- **`code_walkthrough`** — the code must be real and runnable-looking, short enough to read on
  screen, and the highlighted lines must be the ones the narration is actually about. Prefer
  eight clear lines to twenty realistic ones; elide with a comment rather than truncating
  mid-statement. Highlight one region, not four.
- **`stat_callout`** — the value is the whole scene, so it must be a number a viewer can hold:
  round it, and put the precision in the context line if precision matters. The context says why
  the number is surprising, not where it came from.

  **`value_number`, `prefix`, `suffix` (added in this pack version):** set `value_number` to the
  plain numeric value `value` renders as — 200000 for "200,000", 94 for "94%" — and the animated
  tier counts up to it live instead of only scaling in. Fill it whenever `value` *is* a clean
  number: an integer or a value with at most one decimal place, with no qualifier baked into the
  digits themselves. Leave it `null` when `value` is a ratio ("1 in 5"), a range, an
  approximation the narration itself hedged ("about half", "roughly 3 billion"), or anything a
  count-up would make look more precise than it is — counting up to a number implies that number
  is exact, and a viewer reads a count-up as a fact being *proven*, not estimated. Put a symbol
  that reads as part of the number itself in `suffix` ("%", "x", "ms") and a unit set apart from
  it in `unit` (unchanged from this pack's earlier guidance) — not both for the same thing.
  `prefix` is for a leading symbol like "$". Never derive `value_number` by parsing `value`'s
  text; decide it independently from the same fact `value` was built from, the same rule that
  already governs not inventing a number for any other slot.

## Consistency with the narration

The scene must not contradict the narration, and must not introduce a fact the narration never
mentions. If the narration says "roughly ten times", the stat says "10x" — not "9.7x" because it
seemed more credible. **Never invent a number for a slot.** If the intent needs a figure the
narration does not supply, use the qualitative phrasing the narration used.
